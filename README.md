# 智聘千寻 · AI 招聘工作台

面向中大型企业的 AI 招聘管理平台前端实现。覆盖职位发布、简历上传与解析、候选人推进、面试安排、Offer 审批、组织与权限、企业设置、消息通知，以及 AI 中心与数字人面试间。

本项目是**可直接运行的高保真交互产品原型**：所有核心业务链路可操作，数据保存在浏览器 `localStorage`；AI 生成、简历解析、消息发送等外部能力以可信的产品化交互模拟，接口位置已按生产化方式预留。

## 运行

```bash
npm install
npm run dev
# http://localhost:3000
```

- 登录页：`/login`，演示账号已预填（`lin.lan@chengming.ai` / `demo2026`），任意非空账号也可进入。
- 演示数据：首次访问自动写入 `localStorage`，键为 `zhipin-qianxun-v1`。
- 重置数据：右上角头像菜单 →「重置演示数据」。
- 生产构建：`npm run build && npm start`。

## 为什么选择 shadcn/ui 而不是 HeroUI / Aceternity / Vercel

| 方案 | 本质 | 许可证 / 费用 | 对本项目的适配 |
| --- | --- | --- | --- |
| **shadcn/ui + Radix + Tailwind** ✅ | 可复制的组件源码 + 无障碍原语 | MIT，免费 | 高密度数据表格、抽屉、权限矩阵、复杂表单都需要完全掌控视觉与行为；设计系统可完全自定义，不被组件库默认风格绑架 |
| HeroUI | 基于 React Aria 的 npm 组件包 | MIT / Apache-2.0，免费；Pro 组件付费 | 开箱质量好，但默认风格强、深度定制成本高；数据网格与命令面板在 Pro 层 |
| Aceternity UI | 营销页动效与区块 | 免费组件 + 付费模板（$169–$199） | 更适合落地页与品牌页，不覆盖企业后台需要的表格、日期、权限等基础组件 |
| “Vercel” | 不是组件库，是 Next.js / Geist / v0 生态 | Next.js MIT，免费 | 作为框架层采用 Next.js；视觉组件仍应使用 shadcn/ui 这类可拥有源码的原语 |

结论：**Next.js 16 + TypeScript + Tailwind CSS v4 + shadcn/ui 模式（Radix 原语 + 自有组件层）+ Lucide + Sonner**。Aceternity 的动效适合未来做官网/落地页，而不是本产品的后台界面。

## 设计系统：Signal / 信号

招聘的本质是从噪声中识别信号。设计语言围绕“信号、校准、判断”展开，而不是通用 SaaS 的紫色渐变或卡片堆叠。

- **色彩**
  - Ink `#12201b`：主文字
  - Paper `#f2f4ef`：工作区画布（冷调米灰，不是暖奶油色）
  - Pine `#0c4539` / Pine Deep `#072f27`：品牌主色、导航与 AI 场景
  - Signal `#df4f2c`：AI 动作、关键提醒、决策窗口
  - Amber `#d99a32`：审批 / 待处理
  - Line `#e2e7df`：发丝级边界
- **字体**
  - 中文：PingFang SC / Microsoft YaHei / Noto Sans SC 系统栈
  - 拉丁与数字：Sora Variable（本地 npm 字体包，免费开源）
  - 数字统一启用 tabular numerals，匹配度、薪资、时间不跳动
- **布局**
  - 深松绿侧栏 + 纸感工作区 + 少量朱砂强调
  - 内容最大宽度 1520px，桌面高密度、移动端卡片化
  - 卡片圆角 16–20px，控件 9–10px；不使用“所有元素同一个圆角”的模板感
- **标志性元素**
  - 工作台顶部的“AI 今日招聘简报”——深色信号场 + 轨道图，是全站唯一的强视觉时刻
  - 匹配度环形仪表、招聘漏斗、岗位画像雷达
  - 数字人面试间：双画面 + 实时转写 + 实时评分
- **动效**
  - 只保留有意义的过渡：抽屉滑入、生成步骤推进、列表淡入
  - 全局尊重 `prefers-reduced-motion`

## 已接通的交互链路

- 发布职位 → 自动出现在职位列表与工作台统计
- 上传简历 → AI 解析进度 → 批量生成候选人 → 写入通知记录
- 候选人详情 → 推进阶段 / 安排面试 / 创建 Offer / 发送消息 / 归档
- 安排面试 → 候选人时间线 + 面试列表 + 通知记录
- 面试详情 → 进入数字人面试间 → 结束面试生成纪要
- 提交面试反馈 → 面试记录与候选人时间线同步
- 创建 Offer → 审批流 → 发送 / 接受 / 拒绝
- 消息模板 → 启用停用 / 编辑 / 变量预览 → 通知记录
- 角色权限 → 权限矩阵保存 → 成员角色同步
- 企业认证 → 招聘授权状态更新
- 全局 `⌘K` 搜索（页面 / 职位 / 候选人 / 面试）
- AI 助手「小聘」：全局浮层对话 + 页面上下文建议

## AI 能力的生产化接入

当前 AI 输出为**按真实业务结构编排的模拟内容**，优势是交互、信息架构与可追溯形态已经完整。接入真实服务时建议替换以下边界：

1. `app/(app)/ai/page.tsx` 的 `run()`：替换为流式 LLM 调用（SSE / WebSocket），保留 4 步进度与结果确认。
2. 简历解析：`components/candidates/upload-dialog.tsx` 的 `start()`，接入文档解析 + LLM 结构化抽取，返回姓名/联系方式/经历/技能/匹配度。
3. 数字人面试：`app/interviews/live/[id]/page.tsx`，接入 RTC（声网/腾讯云）与数字人驱动、ASR/TTS、结构化评分。
4. 岗位画像与推荐报告：将 `Job.aiProfile`、`Candidate.ai` 替换为服务端生成的版本，并保留人工校准入口。
5. 消息发送：`lib/store.tsx` 中新增通知记录的位置接入邮件/短信服务商，补充发送回执与重试队列。
